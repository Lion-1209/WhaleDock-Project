# 鲸屿 WhaleDock · 开发环境搭建（Windows）

> 目标读者：固件/上位机开发者与二开贡献者。
> 核心原则：**所有大文件下载走 CLI（进度看得见），不走 VS Code 新建工程向导（黑盒“卡住”的根源）**。
> 一次性成本：首次构建下载约 1GB（交叉工具链 + Arduino core），缓存在 `%USERPROFILE%\.platformio`，此后所有项目共用，不会再下。

## 0. 前置清单

| 工具 | 要求 | 检查命令 |
|---|---|---|
| Windows | 10/11 x64 | — |
| 原版 VS Code | 不用 Cursor/VSCodium 分叉（PlatformIO 插件在分叉市场上有安装问题） | `code -v` |
| Git | 任意近期版本 | `git --version` |
| Python | ≥ 3.9（仅用于安装 PlatformIO Core） | `python --version` |

> Node.js LTS 仅上位机开发（`console/`）需要，纯固件开发可不装。

## 1. 安装 PlatformIO

1. VS Code 扩展市场搜索 **PlatformIO IDE** 安装（扩展内置 PlatformIO Core）。
2. 验证：新开终端执行 `pio --version`。若提示找不到命令，把 `%USERPROFILE%\.platformio\penv\Scripts` 加入 PATH，或直接用 VS Code 内置终端。

## 2. 配网络（关键步骤，别跳过）

PlatformIO 的下载源（registry.platformio.org / dl.platformio.org / GitHub Release）国内直连基本拉不动，这就是“新建工程卡住”的根源。三选一：

- **方案 A（推荐）：本地代理 + 环境变量**

  PowerShell 执行：
  ```powershell
  setx HTTPS_PROXY "http://127.0.0.1:7890"   # 换成你自己的代理端口
  ```
  然后**完全退出 VS Code 再重开**（`setx` 只对新进程生效，只关窗口不一定够）。PlatformIO Core 读取标准代理环境变量。

- **方案 B：TUN / 全局模式**（Clash TUN 等）：流量被全局接管，零配置。

- **方案 C：完全没有代理** → 直接跳到 §5 离线种子。
- **方案 D（本机实测）：开了 Watt Toolkit（Steam++）网络加速的机器** → 见下方"Watt Toolkit 专项"，跑一次 `tools/fix-tls-bundle.ps1` 即可。

验证代理生效：终端跑 `pio run`（见 §4），能看到下载速度即通。

### Watt Toolkit 专项（2026-09 本机实测）

装了 Watt Toolkit 并开启"网络加速"的机器，github.com 会被它本地 MITM 重签证书（签发者 `SteamTools Certificate / BeyondDimension`）。后果：git 克隆正常（走 Windows 证书库），但 PlatformIO / pip / Node 里所有走 OpenSSL+certifi 的下载全部报 `certificate verify failed`——**这也是"新建工程卡住"的一种隐蔽成因**。

一次性修复（把 Windows 证书库导出为 PEM，喂给 Python 各条验证路径）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\fix-tls-bundle.ps1
# 完成后重开终端 / 完全重启 VS Code
```

或者干脆在 Watt Toolkit 里正常关闭网络加速（注意要在界面里关，让它把 hosts 里的 127.0.0.1 条目撤掉；直接杀进程会残留 hosts 导致 github 彻底断连）。

## 3. 关联网检查 + Defender 提速

```bash
pio settings set check_platformio_interval 0   # 关 PlatformIO 自更新检查
pio settings set check_libraries_interval 0    # 关库索引周期检查
```

管理员 PowerShell 执行（工具链解压要写几千个小文件，不排除 Defender 实时扫描会慢得像死机）：
```powershell
Add-MpPreference -ExclusionPath "$env:USERPROFILE\.platformio"
```

## 4. 首次构建（CLI，进度可见）

```bash
cd <本仓库>/firmware
pio run
```

- 预期下载约 1GB：pioarduino 平台 + xtensa 工具链 + Arduino core 3.x + GxEPD2，终端有实时进度条；
- **失败或中断后直接重跑同一条命令**，已下载的包不会重下；
- 成功标志：`SUCCESS`，产物在 `firmware/.pio/build/whaledock/firmware.bin`。

版本已锁死在 `platformio.ini`（平台 tag `55.03.39` / GxEPD2 `^1.6.9`），任何人任何时间构建产物一致——40 台量产烧录一致性依赖于此。**不要**把平台源改回 PlatformIO 官方 `espressif32`（那是 Arduino core 2.x / IDF 4.4 旧栈，已 EOL）。

## 5. 无代理环境：离线种子

1. 网络正常的机器完成 §4 后打包：
   ```powershell
   Compress-Archive -Path "$env:USERPROFILE\.platformio" -DestinationPath pio-seed.zip
   ```
   （约 1–2GB，网盘/U盘传给队友）
2. 队友解压到自己的 `%USERPROFILE%\.platformio`，从 §1 第 2 步继续，跳过 §2 与 §4 的下载。

## 6. 烧录、监视、调试

```bash
pio run -t upload       # 编译 + 烧录；esptool 自动复位进下载模式，无需手按 BOOT
pio device monitor      # 串口监视（115200，已配 esp32_exception_decoder 自动解栈）
```

- 接 ESP32-S3-DevKitC-1 上标 **"USB"** 的 Type-C 口（原生 USB CDC + USB-JTAG 同口），不是 "UART" 口；
- 一根 USB-C 线 = 供电 + 烧录 + 断点调试 + Web Serial 四合一，**不需要任何外置调试器**；
- 断点调试：VS Code 里 PlatformIO 的调试按钮直接走内置 USB-JTAG（OpenOCD + GDB），`info tasks` 可看 FreeRTOS 任务列表。

## 7. 谁不需要装这套环境

| 角色 | 用什么 |
|---|---|
| 二开者（只刷固件） | GitHub Actions 产出的 firmware 附件 + [esptool](https://docs.espressif.com/projects/esptool/) 或 Flash Download Tool |
| 产线烧录首检 | 同上 + 上位机网页（Web Serial），不装 PlatformIO |
| 上位机开发者 | Node.js LTS，无需 PlatformIO |

## 8. 常见问题

| 症状 | 原因与解法 |
|---|---|
| VS Code 向导卡在 "Installing platforms" | 向导是黑盒后台下载。别等它，终端跑 `pio run` 看真实进度；大概率代理没生效（回到 §2，注意 `setx` 后要完全重启 VS Code） |
| `pio run` 下载平台/工具链失败或龟速 | 代理未生效或 GitHub 间歇阻断；多重跑几次（续传）；确认 §2 |
| 下载报 `CERTIFICATE_VERIFY_FAILED` 但 git 克隆正常 | 本机 MITM（常见于 Watt Toolkit 加速），见 §2 Watt Toolkit 专项，跑 `tools/fix-tls-bundle.ps1` |
| `pio` 报 `Failed to install Python dependencies` / `uv ... Failed to inspect Python interpreter` | penv 坏了。多半是系统 Python 残缺（如 `C:\Python314` 缺 `Lib/` 目录）导致 venv 派生就坏。修复：删 `%USERPROFILE%\.platformio\penv`，用 PlatformIO 自带便携 Python 重建：`~/.platformio/python3/python.exe -m venv ~/.platformio/penv`，再 `~/.platformio/penv/Scripts/python.exe -m pip install --index-url https://pypi.tuna.tsinghua.edu.cn/simple platformio` |
| `python -c` 打印 `Could not find platform independent libraries <prefix>` | 系统 Python 安装残缺（缺标准库）。卸载重装完整版 CPython，或直接不用它（PlatformIO 有自带便携 Python） |
| 编译报 `xtensa-esp32s3-elf-g++ 不是内部或外部命令`，且 `~/.platformio/packages/toolchain-xtensa-esp-elf` 只有十几 KB | pioarduino 的工具链包是"存根 + 二次拉取"设计：存根 zip 只含 tools.json，真工具链（GB 级）由 `tool-esp_install` 的 `idf_tools.py` 装到 `~/.platformio/tools/`。二次拉取当时失败（网络/坏 Python）就会留下永远"已安装"的空壳。修复：手动跑 `idf_tools.py --tools-json <存根>/tools.json install`，且必须去掉 `MSYSTEM` 环境变量（Git Bash 注入且 unset 无效；从 PowerShell 跑且先 `Remove-Item Env:MSYSTEM`，否则报 "MSys/Mingw is not supported"） |
| 构建中断后某包"已安装"却没内容 | PlatformIO 下载缓存不校验内容，`~/.platformio/.cache/downloads/` 按 `sha1(URL)` 命名。删掉对应哈希文件 + `~/.platformio/packages/<包名>` 后重跑 `pio run` 重新下载 |
| 自检打印 `PSRAM 0 MB` | 板子不是 R8（Octal PSRAM）型号，或 `platformio.ini` 里 `memory_type=qio_opi` 被改动 |
| 屏幕花屏/白屏/倒像 | 99% 是驱动类与屏不符：核对屏 FPC 排线丝印——GDEW075Z08 → `GxEPD2_750c_GDEW075Z08`，GDEY075Z08 → `GxEPD2_750c_GDEY075Z08`（改 `src/main.cpp` 的 `using DisplayT` 一行）；其次是排线过长/杜邦线飞线、供电不足 |
| 找不到串口设备 | 插错口（要用 "USB" 口）；换一根能传数据的线（很多线只供电） |
| monitor 中文乱码 | 波特率须为 115200；VS Code 监视器编码选 UTF-8 |
| 全刷 15–25 秒“像死了” | 三色墨水屏物理特性，正常；**期间勿断电** |
